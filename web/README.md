# web — AfnaiHisab

Next.js (App Router, TypeScript) front end. It talks to the Ktor backend over HTTP only and is
deliberately outside the Gradle build — it is not a KMP target (ADR-0003).

## Run

```bash
npm ci        # exact versions from package-lock.json (ADR-0017)
npm run dev   # http://localhost:3000
```

The page calls `GET /api/v1/health` **from the browser**, so it needs `server` running
(`./gradlew :server:run` from the repo root) and the browser's origin on the backend's CORS
allow-list (ADR-0015). If the backend is somewhere other than `http://localhost:8080`, copy
`.env.example` to `.env.local` and set `NEXT_PUBLIC_API_BASE_URL`.

## Scripts

| Command                                   | What                                              |
| ----------------------------------------- | ------------------------------------------------- |
| `npm run dev`                             | Dev server                                        |
| `npm run build`                           | Production build — also type-checks the whole app |
| `npm run lint`                            | ESLint                                            |
| `npm run format` / `npm run format:check` | Prettier write / verify                           |

## Conventions

- `lib/api.ts` is the only module that knows the backend's URL and error-envelope shape.
  Components consume it; they do not call `fetch` directly.
- Prettier owns formatting, ESLint owns everything else — `eslint-config-prettier` sits last in
  `eslint.config.mjs` so the two never disagree.
- `AGENTS.md` in this directory is generated by `next dev` and points at Next 16's bundled docs in
  `node_modules/next/dist/docs/`. Read those before writing web code; this Next version differs
  from older conventions.

Repo-wide conventions and the full dev-stack instructions live in the root `CLAUDE.md`.
